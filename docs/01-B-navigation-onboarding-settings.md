# TripCanvas — 1-B 앱 탐색 구조 및 초기 화면

- 기준: 2026-11-09
- 선행: [0-A 기능 요구사항](./00-A-product-requirements.md), [0-B 화면 설계](./00-B-screen-spec.md), [1-A 공통 디자인 시스템](./01-A-android-foundation-design-system.md)
- 진행 범위: S00 첫 실행, S01 빈 홈/필터, S03 여행 상세 정보 구조(미리보기), S20 설정, Navigation Compose, DataStore
- 구현 범위 외: 실제 여행 생성·수정·삭제, Room 여행 목록, 장소·경비 입력, 백업/복원, 로그인, 지도, 클라우드, 배포

## 1. 기술 선택

- Navigation Compose: `androidx.navigation:navigation-compose:2.10.2`
- DataStore Preferences: `androidx.datastore:datastore-preferences:1.2.1`
- 프로젝트 기존 Kotlin·Compose·Material 3·Gradle 및 `com.hebi.tripcanvas` 패키지 유지.
- 기존 `TripCanvasTheme`, `TripChoiceChip`, `TripPrimaryButton`, `TripSurfacePanel`, `TripEmptyState`, `TripErrorState`, `TripLoadingState`, `TripAdaptiveContainer` 재사용.

## 2. 화면·탐색 정책

| 화면 | Route | 구현 | 이동 |
| --- | --- | --- | --- |
| S00 — 첫 실행 | welcome | 최초 시작 안내·로컬 저장 원칙·단일 CTA | DataStore 완료 상태 기록 후 S01로 전환 |
| S01 — 홈 | home | 여행 0건 안내, 전체/예정/여행 중/완료 빈 목록 필터 | 설정 진입 |
| S03 — 여행 상세 미리보기 | workspace-preview | 일정·경비·준비물의 정보 구조, 실제 데이터 없음 표시 | 설정에서 미리보기 → 뒤로 가기 |
| S03 — 여행 상세 실데이터 경로 | trip/{tripId} | 경로 자리만 준비. 2-A 데이터 연동 전에는 데이터 부재 안내 | 실사용 진입은 아직 노출하지 않음 |
| S20 — 설정 | settings | 시스템·라이트·다크 선택, 저장 상태·오류, 추후 기능 범위 고지 | 홈/미리보기 이동 |
| 1-A 디자인 갤러리 | design-system-preview | 기존 공통 컨트롤 미리보기 유지, 테마 설정 연동 | 설정에서 열기/뒤로 가기 |

- S00은 첫 실행 완료 전만 시작 목적지로 사용한다. DataStore 저장 완료 후 그래프를 홈 시작으로 재구성하므로 뒤로 가기로 S00에 복귀하지 않는다.
- 홈의 '새 여행'은 미구현이므로 disabled 상태로 표시하며 이유와 2-A 예정 단계 텍스트를 함께 표시한다. 무효/허위 여행 데이터를 생성하지 않는다.
- S01 필터는 선택 시 빈 상태 안내 문구를 변경하지만 여행 목록 검색 기능 완료를 의미하지 않는다.
- S03은 설정의 '화면 검수'에서만 미리보기를 열 수 있다. 실제 여행 데이터·통계 또는 가짜 여행을 보여주지 않는다.
- 각 화면은 단일 세로 스크롤 및 정보 위계, 48dp 이상 주요 CTA, 라이트/다크 시맨틱 토큰을 사용한다.
- Navigation 전환 애니메이션은 추가하지 않으며, Android 뒤로 가기는 이전 화면으로 이동한다.

## 3. DataStore 정책

설정 파일: `tripcanvas_preferences.preferences_pb` (Android DataStore 기본 네이밍 규칙에 의해 생성).

| 키 | 형식 | 기본 | 쓰기 시점 |
| --- | --- | --- | --- |
| `onboarding_completed` | Boolean | false | S00 '여행 시작' 선택 후 원자적 DataStore edit 성공 시 |
| `theme_mode` | String | System | S20 또는 갤러리의 테마 선택 후 원자적 DataStore edit 성공 시 |

- DataStore는 애플리케이션 컨텍스트 단위의 단일 인스턴스를 사용한다.
- 최초 값 로딩 전에는 로딩 상태를 표시한다. 기본값을 근거로 S00을 잠시 표시했다가 홈으로 전환하는 깜빡임을 피한다.
- 읽기 오류에서는 오류 안내·재시도를 제공하고 임의로 첫 실행 완료 플래그를 변경하지 않는다.
- 저장 중 중복 제출을 막고 실패 시 기존 선택값을 유지하고 오류를 표시한다.
- 모르는 `theme_mode` 문자열은 시스템 테마로 처리한다. 저장 키가 없으면 온보딩 미완료/시스템 테마로 처리한다.
- 저장 위치는 앱 전용 저장소이며 계정·클라우드 동기화는 추가하지 않는다.
- 앱의 기존 `android:allowBackup="false"` 설정은 유지한다. 다른 기기로 자동 복원되는 기능을 구현했다고 표시하지 않는다.

## 4. S00 상세

- 첫 화면은 브랜드명, 제목, 앱의 목적, 데이터 관리 정책을 보여준다.
- 로그인, 사진, 위치, 알림 권한은 요청하지 않는다.
- '여행 시작' 클릭 시 DataStore 편집을 수행하고 반영 완료 뒤 홈을 시작 화면으로 연결한다.
- 네트워크 없이도 동작. 저장 실패 시 오류를 표시하고 다시 선택할 수 있다.
- 글꼴 확대에서도 본문과 버튼은 단일 세로 스크롤로 접근 가능.

## 5. S01 상세

- 홈 상단 TripCanvas/설정, '내 여행' 제목, 전체/예정/여행 중/완료 필터.
- 여행 데이터 저장을 구현하지 않았으므로 항상 0건 빈 상태를 노출한다.
- '새 여행' CTA는 보이되 비활성화. 2-A 단계에서 연결할 때 기존 CTA를 활성화한다.
- 필터 선택 상태는 화면 재구성 시 가능한 범위에서 유지하며, 사용자에게 존재하지 않는 여행 데이터가 있는 것처럼 표현하지 않는다.

## 6. S03 상세

- 여행 상세의 상단 타이틀·관련 영역을 1-A 디자인 컴포넌트로 표시한다.
- 휴대폰: 일정/경비/준비물 1열. 너비 600dp 이상: 양쪽 두 열, 영역별 정보를 분리한다.
- 가짜 여행 기간/돈/사진을 넣지 않으며, 명시적인 '미리보기' 상태만 표시한다.
- `trip/{tripId}`는 2-A에서 실제 로컬 Repository를 연결하기 위한 목적지 형태만 준비한다.

## 7. S20 상세

- 화면 모드: 시스템/라이트/다크 선택. 변경 결과는 DataStore를 통해 재구성되며 재실행 뒤에도 유지된다.
- 다른 여행 기본값과 백업은 미구현 안내만 표시한다.
- 미리보기 진입 버튼은 실제로 이동할 수 있고 Android 뒤로 가기로 설정에 복귀한다.
- 1-A 갤러리에서 변경한 테마도 동일 저장소에 반영하여 설정과 어긋나지 않게 한다.

## 8. QA·수용 기준

| 검사 | 기대 결과 |
| --- | --- |
| 새 설치 직후 실행 | S00 진입, 권한/로그인 없이 이용 |
| 시작 버튼 중복 탭 | 단 한 번의 완료값 저장, 완료 후 홈 시작 |
| 앱 강제 종료·재실행 | S00 재출현 없음, S01 시작 |
| 라이트·다크·시스템 선택 | 앱 UI와 상태바 아이콘 대비 동기화 |
| 테마 바꾼 뒤 재실행 | 마지막으로 저장한 모드 유지 |
| 모르는 테마 설정 값 | 시스템 테마로 안전하게 복구 |
| 읽기/쓰기 오류 | 원본 유지, 오류 노출/재시도 |
| 홈 설정→미리보기→뒤로 | 미리보기에서 설정으로, 설정에서 홈으로 이동 |
| 360dp·태블릿·폴더블·160% 글꼴 | 중요 텍스트·버튼 접근 가능, 중첩 세로 스크롤 없음 |
| 오프라인 상태 | 첫 실행·홈·설정/테마 사용 가능 |
| 여행 CRUD 미구현 | 허위 데이터·액션 노출 없음 |

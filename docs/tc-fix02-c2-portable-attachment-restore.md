기준 main: eefab18c808ee80b380fdc46f22a11752fc19ce8. PR #75에서 C1과 C2를 통합한다. C1 HEAD 7964a678ee2acf32a1e33d4a8d951f10d3de18ba Android/JVM 및 OPS 성공. A06 #45522650848은 Maven Central HTTP 429로 UTP 의존성 다운로드 실패하여 실제 계측 미완료. 의존성/테스트 안전 게이트 변경 없이 통합 HEAD에서 재검증한다.

## 복원 경계
- 별도 .tcm 선택, 비밀번호 입력, 전체 GCM 인증 완료 후 엄격한 ZIP 엔트리 순서, 고정 생성 경로, 개별/합계 용량 및 파일 개수, 구조화 JSON 검증, manifest 버전·소유 ID·길이·SHA-256·사진 placeholder·예약 링크 정합성 확인. 미리보기는 DB 및 파일에 기록하지 않는다.
- 미리보기 후 명시적 전체 교체 승인. 같은 암호화 파일의 SHA-256 재검증 및 다시 인증/manifest 확인 후 새 앱 전용 UUID 폴더에 원본 복사, fsync 및 content URI readback 해시 검증. 원본 URI·사용자 파일명을 저장 경로로 사용하지 않는다.
- 앱 비공개 FileProvider의 restored_media 경로만 사용하며 읽기 전용으로 제공한다. 동일 기기의 현재 DB/안전 백업에 연결 가능하며 다른 기기에서는 새 URI를 생성한다. 암호화는 백업 파일에 적용되며 복원한 파일은 앱 전용 저장소에 원본 바이트로 보관한다.
- 복원 전 안전 백업 저장/재검증 및 기존 Room 트랜잭션 안에서 데이터와 예약 첨부 행 교체. 실패 시 새 파일 묶음 정리, 기존 데이터/외부 원본 변경 없음. DB 성공 이후 취소가 새 참조 파일을 삭제하지 않도록 최종 교체 및 성공 표시를 non-cancellable 경계로 묶었다. 프로세스 강제 종료/기기 전원 손실의 파일·DB 공동 원자성은 별도 검증 필요.
- 복원 파일 누적 한도 200MiB. 명시적 정리 승인 시 현재 DB와 최신 안전 백업이 모두 참조하지 않는 앱 내부의 생성된 파일 묶음만 삭제. 잘못된 참조/복구본 검증 실패 시 정리 중단. 외부 원본·사용자가 생성한 백업 파일에는 접근/삭제하지 않음. 일부 파일만 참조하더라도 전체 묶음은 보존한다. 안전 백업 삭제 후 정리 가능하며 앱 제거/데이터 삭제 시 앱 내부 복원 파일도 삭제된다.

## 2. 공통 기준

Travel Editorial 기존 토큰 유지. 직각·1dp 외곽선, 검정/회색/흰색, 기존 다크 테마, 상태별 의미 색, 기존 최소 터치 영역. 기존 데이터 계층과 인증/광고/백업/배포 정책 보존. 생성 이미지 사이에 상이한 그림자, 라운드, 사진은 기존 확정 기획을 우선한다.

## 3. 실제 화면 캡처 조건

일반 PR의 장시간 기기 QA 생략 정책을 바꾸지 않는다. 사용자가 요청한 1:1 실제 화면 비교 목적에 한해 이 디자인 브랜치에만 적용되는 read-only 폰 캡처 작업을 별도 구성한다. 기존 2C/3A/3B 스크립트를 API 35, 1080×2400, density 420의 실제 에뮬레이터에서 호출하고 후보 SHA 및 원본 PNG·테스트 로그를 보존한다. Play/서명/스토어 자산/서버 작업 없음. 전체 최종 main API 29/35/36 및 폰/태블릿 QA는 기존 절차를 따른다.

기존 테스트 데이터(제주 주말 여행/장소 여행/동행 여행, 일정 날짜·지출 등)는 디자인 샘플과 다르다. 실제 레이아웃 대조 시 데이터를 구별하며 픽셀 일치율이나 임의 점수를 산정하지 않는다. 완료 전 캡처가 없거나 실패하면 실제 1:1 비교는 미검증이다.

## 4. 남은 작업

- 최신 후보 CI와 실제 화면 캡처 성공 확인, 원본별 1:1 이미지 비교.
- 화면별 남은 위치/높이/간격/폰트/터치 영역 차이 수정 및 재검증.
- 첫 실행 및 나머지 34개 설계 프레임의 추가 상세 비교와 폴더블/다크/오류 상태 확장.
- 최신 검증 없이는 병합하지 않는다. 전체 개발과 QA 후 별도 승인 없이는 Google Play 배포하지 않는다.

# UI-R05 — 경비·정산 정보 구조 개선

작업 기준일: 2026-11-11 / TripCanvas S09~S11, UI-R00~R09 기획 디자인·실제 Android 화면 비교
기준 선행 브랜치: `ui/ui-r04-checklist-20261111`. 선행 UI-R02 PR #27 병합, UI-R03 PR #28 및 UI-R04 PR #29의 QA·순차 병합 완료 전 UI-R05 직접 main 병합 금지.

## 변경 배경

현행 경비 화면은 동행자 정산·관리 버튼이 예산 및 지출보다 먼저 노출되어, 사용자의 핵심 질문인 총예산·지출합계·잔액 확인을 방해함. 정산 화면은 개인별 지불·부담 근거가 송금 제안보다 먼저 노출되어 결론을 찾기 위해 스크롤이 필요함.

## 구현 범위

### 1. 경비 화면 — ExpenseListScreen
- 여행명 및 기본 통화 정보 직후 '예산 현황'을 배치. 단일 테두리 패널에 '총예산 / 지출 합계 / 잔액' 표시.
- Compact 0~599dp 1열, Medium·Expanded 600dp 이상 3열. 기존 Travel Editorial 흑백/회색·직각 카드·그림자 0 유지.
- 예산 미설정 또는 저장 예산 통화가 현재 기본 통화와 다를 경우 잔액은 '비교 불가'로 안내. 기존 예산 값은 별도 문장으로 보존. 임의 환산이나 영(0) 표시 금지.
- 계산 값은 기존 `calculateExpenseTotals`의 `baseSpent`와 실제 현재 통화의 예산 값으로만 구성. 초과 지출 시 초과 금액/경고 색상으로 표현하되 계산식 변경 없음.
- 환율 없는 외화는 기존 '환산 필요' 섹션으로 별도 노출. 기본 통화 합계/잔액에 합산하지 않음.
- '지출 추가' 주 CTA를 요약 및 환산 경고 다음에 두고, 빈 상태의 중복 CTA 제거. 지출 카드의 날짜 그룹·카테고리·장소·메모·환율 출처·편집/삭제/환율·분담 동작은 유지.
- '동행자 정산' / '동행자 관리' 두 보조 버튼은 지출 목록 아래 '동행자·정산' 섹션으로 이동.

### 2. 정산 화면 — TripSettlementScreen
- 정산 상태/기존 '정산 보류' 경고 아래에 '정산 제안 N건' 및 실제 참가자별 송금 방향·금액을 최우선 배치. 실제 송금 기능은 제공하지 않는다는 설명 유지.
- 미환산·분담 미완료 항목이 있을 때 송금 제안이 비어 있으면 '완료되지 않은 지출이 제안에서 제외됨'을 명시. '송금액 없음'이라고 오해하도록 표현하지 않음.
- 기존 정산 확인/완료 표시 철회 CTA와 오류 안내는 송금 제안 바로 다음에 배치.
- 참가자별 '지불 / 부담 / 받을 금액·낼 금액' 세부 계산 근거 및 동행자 관리, 지출별 환율·분담 검토 버튼은 아래로 이동.
- `calculateSettlement`, `fingerprint`, `readyToConfirm`, 확인 무효화 및 재계산 로직은 변경 없음.

## 기능 보존 / 제외

- Room DB·DAO·Repository·백업/복원·환율 계산·통화 검증·금액 최소단위 배분, 정산 fingerprint, 여행별 데이터 격리 불변.
- 기존 2-C / 3-A / 3-B 화면 진입 및 계측 선택자(예산 설정·변경, 지출 추가, 정산 제안 N건, 정산 확인, 환율·분담 설정) 유지.
- 신규 라이브러리·네트워크 환율·금전 송금·계정/협업·광고·배포 설정·스토어 이미지 변경 없음.

## 검증 범위

- Android Debug 빌드/JVM 단위 테스트, API35 Room Migration / 2-C 휴대전화·태블릿 실제 UIAutomator / 3-A 지도 / 3-B 경비·정산·예약 / API29·36 런치·폰트 160% 회귀.
- 2-C: 실제 예산 KRW 300,000에서 KRW 12,500 지출과 미환산 USD 12.50을 구분; '예산 현황'·'총예산'·'지출 합계'·'잔액'·'KRW 287,500 남음'·'환산 필요' 확인, 라이트·다크·160% 실제 PNG.
- 3-B: USD 10.00 * 사용자가 지정한 환율 1320, 참가자 민재/현지 6600씩 분담 → '현지 → 민재 · KRW 6,600' 송금 제안 표시 및 '참가자별 지불·부담' 아래 확인, 정산 확인·지출별 환율/분담·예약 첨부 기존 회귀.
- 화면 검수: 휴대전화 Compact·태블릿 Expanded, 라이트/다크·160%에서 숫자 잘림, 보조 CTA 접근, 미환산 안내 가독성, 스크롤/터치/접근성. 물리 실기기·TalkBack·폴더블은 별도 미검증으로 표기.
- CI 성공만으로 원본 PNG 시각 검수·Play 게시 승인을 의미하지 않음.

## 병합·배포 게이트

1. PR #28 UI-R03 및 PR #29 UI-R04가 정확한 HEAD의 필수 CI·실제 PNG 시각 QA를 마친 뒤 main에 순차 병합되었는지 확인.
2. UI-R05는 선행 R04 브랜치 기반 Draft로 유지. 선행 단계가 병합되면 PR base를 최신 main으로 재지정하고 실제 diff/충돌·필수 CI·화면 캡처를 새 HEAD에서 재검증.
3. 검증 전 main 병합 및 Play closed/production 승격 금지. main에 병합 시 기존 `play-internal.yml` 자동 실행 가능성을 별도로 확인하고 실제 릴리스 API 응답/서명/트랙 상태로만 배포 판정.

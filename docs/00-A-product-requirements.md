## 1. 제품 목적과 경계

TripCanvas는 하나의 여행(Trip)을 중심으로 일정, 장소·지도, 예약 문서, 동행자, 지출·정산, 방문 체크인, 사진 기록, 리포트를 연결한다. 추천 피드가 아니라 실제 계획→현장 실행→여행 후 정산 및 회고를 주 사용자 여정으로 삼는다.

대상: ① 혼자 자유여행을 계획하는 사람 ② 친구·연인·가족 등 공동 여행자 ③ 여행 후 실제 방문·사진·경비를 정리하려는 사람.

지켜야 할 원칙:
1. 사용자 데이터는 여행 단위로 소속되고, 일정·장소·지출·사진 사이 연결이 분명해야 한다.
2. 최초 버전은 계정 없이 로컬에서 동작한다. 추가 네트워크 기능은 해당 기능 이용 시에만 필요하다.
3. 앱에 표시된 예상 이동 시간·거리·운영 시간은 실제 데이터 제공자와 갱신 시점을 표시한다. 미확인 값은 표시하지 않는다.
4. AI·경로 최적화는 제안만 하고 실제 일정은 사용자가 승인한 후 바뀐다.
5. 실제 방문 여부는 기본적으로 사용자가 직접 체크인한다. 상시 위치 수집은 하지 않는다.
6. 서비스 제공 범위는 여행 정보 관리이고 항공권/숙소 예약이나 결제 대행은 아니다.

## 2. 확정 범위와 출시 순서

| 우선순위 | 단계 | 기능 | 포함 여부 |
| --- | --- | --- | --- |
| P0 | 1~2단계 | 여행 생성·수정·삭제, 날짜별 일정/장소 수동 등록, 준비물 체크리스트, 기본 경비, 오프라인 저장, 로컬 백업/복원 기본 설계 | 1차 MVP |
| P1 | 3단계 | 지도/장소 검색, 일정↔지도 연결, 경로 비교, 예산 분석, 참여자별 분담·정산, 예약 문서 | MVP 다음 |
| P2 | 4단계 | 계정, 초대, 소유자·편집자·열람자, 변경 기록, 원격 동기화와 충돌 처리 | 협업 확장 |
| P3 | 5단계 | 오늘의 여행, 체크인, 실제 방문 타임라인, 사진 기록, 여행 리포트 | 현장/회고 |
| P4 | 6단계 | OCR 영수증, AI 일정·동선 제안/요약, 최적화 보조, 선택적 내보내기 고도화 | 고급 |
| 별도 검증 | 7단계 | 접근성·권한·보안·실기기·스토어 QA | 출시 요건 |

P0의 '기본 경비'는 개인별 지출 금액/분류/시각/메모 저장을 뜻한다. 다자간 비용 분담·채무 상계는 P1이다. P0 장소는 이름·주소 메모·선택적 위경도 수동 입력을 지원하며, 외부 장소 검색 또는 지도를 필수로 하지 않는다.

명시적 범위 제외: 실물 예약/결제 중개, 항공·호텔 자동 구매, 사용자 동의 없는 실시간 위치 추적, 자동 지출/일정 확정, 자동 사진 전체 스캔, 구독·로그인 강제, 무제한 온라인 지도 캐싱.

## 3. 핵심 사용자 여정

### J-01 혼자 여행 준비 (P0)
홈 → 새 여행 → 여행명/기간/도시/시간대/통화 입력 → 여행 상세 → 날짜 선택 → 일정·장소 수동 등록 → 준비물 완료 표시 → 지출 등록 → 앱 재실행 → 입력 데이터 유지.

### J-02 여행 동선 정리 (P1)
일정의 장소 선택 → 지도 핀 확인 → 날짜별 순서 확인 → 이동 수단 및 예상 시간 비교 → 제안된 순서를 미리보기 → 사용자 승인 후 일정에 적용. 오프라인에서는 이전 로컬 데이터만 열고 신규 경로 요청은 제한.

### J-03 함께 여행 계획·정산 (P2 + P1)
소유자가 여행 초대 → 동행자가 수락 → 편집자는 일정·공동 지출 수정, 열람자는 읽기만 → 활동 이력 확인 → 결제자와 부담 비율을 반영한 순정산 목록 확인.

### J-04 여행 현장과 종료 (P3)
오늘의 여행 → 다음 장소/예약 정보 → 수동 체크인 → 실제 지출·사진 기록 → 여행 종료 시 예상 대비 방문·비용 확인 → 개인 보관/선택 공유.

## 4. 기능 요구사항 (FR) 및 인수 기준

각 FR의 '완료'는 코드가 존재한다는 뜻이 아니라, 해당 조건을 재현하여 통과한 상태를 뜻한다.

### 4.1 여행 프로젝트

- FR-TRIP-01 [P0] 홈에서 여행 생성. 필수값: 제목(1~80자), 시작일, 종료일, 시간대(IANA ZoneId), 기본 통화(ISO 4217). 종료일이 시작일보다 빠르면 저장 차단.
- FR-TRIP-02 [P0] 선택값: 국가/도시, 여행 목적, 설명, 대표 이미지(추후 단계에서 첨부 활성화). 미입력해도 여행 생성 가능.
- FR-TRIP-03 [P0] 여행 수정 시 연결된 일정·지출·준비물 유지. 기간을 줄여 범위 밖 데이터가 생기면 대상 개수와 날짜를 보여주고, 자동 삭제하지 않음.
- FR-TRIP-04 [P0] 여행 삭제는 여행명 재확인 및 영향 범위 안내 후 수행. 기기에 남은 데이터와 첨부의 삭제 정책 표시; 복구 가능한 백업이 없다면 복구 불가 고지.
- FR-TRIP-05 [P0] 홈은 예정/진행 중/완료 여행을 여행 현지 시간대와 기간 기준으로 분류하며, 사용자가 입력한 여행 데이터를 재실행 후 동일하게 표시.

### 4.2 일정과 장소

- FR-SCH-01 [P0] 여행 기간의 날짜마다 일정 목록 제공. 일정은 시작·종료 시각이 있는 항목과 시간 미정 항목을 모두 지원.
- FR-SCH-02 [P0] 일정 필수값: 제목(1~100자), 날짜. 선택값: 장소, 시작·종료 시간, 메모(최대 2,000자), 중요 표시, 상태.
- FR-SCH-03 [P0] 시작·종료가 모두 있을 때 종료가 시작보다 빠른 경우 저장 차단. 다른 일정과 겹칠 경우 경고만 표시하고 사용자의 저장 선택 허용.
- FR-SCH-04 [P0] 동일 날짜 일정 드래그 순서 조정, 항목 복제, 다른 날 이동, 편집·삭제 가능. 복제해도 원본 식별자·체크인·첨부 기록은 복제하지 않음.
- FR-SCH-05 [P0] 날짜 이동·여행 시간대 변경 후 정렬과 표시 날짜가 명시적 규칙에 따라 유지되며 원본 시각이 임의로 바뀌지 않음.
- FR-PLC-01 [P0] 장소 수동 생성: 이름(필수), 주소/설명, 선택적 좌표; 좌표가 없어도 일정에 연결 가능.
- FR-PLC-02 [P1] 장소 검색 결과에서 주소·공급자·조회 시각을 확인해 저장. 동일 공급자 ID의 장소 중복을 감지하고 기존 항목에 연결 가능.
- FR-PLC-03 [P1] 저장 장소의 지도 핀과 일정 연결을 상호 탐색 가능. 날짜별 후보/확정 장소 시각적으로 구분.
- FR-ROUTE-01 [P1] 이동 수단별 예상 거리·시간과 조회 출처를 제공하는 경우에만 표시. 경로 공급자가 값 미제공 시 '조회 불가'.
- FR-ROUTE-02 [P4] 제안된 방문 순서는 현재 순서와 변경 순서를 비교 후 사용자 승인 시에만 반영.

### 4.3 준비물·예약 자료

- FR-CHK-01 [P0] 여행별 준비물 항목 생성/수정/체크/삭제/정렬. 필수값: 이름(1~100자); 체크 상태와 순서 저장.
- FR-CHK-02 [P0] 완료/전체 개수와 미완료 필터를 표시. 체크 해제 시 원상 복구되며 자동 삭제하지 않음.
- FR-BOOK-01 [P1] 항공·숙소·교통·입장권·기타 예약 종류와 명칭·예약일시·확인번호·메모를 저장.
- FR-BOOK-02 [P1] 문서/이미지 첨부 및 열람; 파일이 이동·삭제된 경우 파일 접근 오류와 대체 작업을 표시.
- FR-BOOK-03 [P1] 예약번호와 민감한 개인 정보는 공개 공유/활동 로그/진단 로그에 자동 포함하지 않음.

### 4.4 예산·경비·정산

- FR-EXP-01 [P0] 여행 기본 통화 기준 총예산(선택) 및 개별 지출 추가/편집/삭제. 필수값: 양수 금액·통화·결제 시각/날짜·분류.
- FR-EXP-02 [P0] 지출은 현지 통화 정밀도로 저장하고 화면은 금액 소수점 자릿수에 맞춰 표시. 내부 산술은 부동소수점이 아닌 십진 기반 계산.
- FR-EXP-03 [P0] 지출 분류: 식비/교통/숙박/관광/쇼핑/기타. 사용자가 메모와 영수증 참조를 추가 가능(첨부는 P1).
- FR-EXP-04 [P1] 총예산 대비 지출, 일자별·카테고리별 내역, 기본 통화 환산 요약을 제공.
- FR-EXP-05 [P1] 기본 통화와 다른 통화의 지출은 해당 지출에 확정된 환산 비율 스냅샷이 있어야 정산 합계에 포함; 값 없으면 '환산 필요'로 별도 표시. 환율 출처/기준일 고지.
- FR-SPLIT-01 [P1] 지출당 결제자, 부담 참가자, 분담 방식(균등/지정 금액/비율)을 기록.
- FR-SPLIT-02 [P1] 분담액 합계는 환산된 지출액과 최소 통화 단위까지 정확히 일치. 균등 분배 잔여 단위는 정해진 참가자 순서로 배정하고 배정 결과를 UI에 표시.
- FR-SPLIT-03 [P1] 참가자별 지불액·부담액·정산 상태를 계산하며 기존 거래 변경 시 재계산. 정산 완료 표시 후 내역 수정 시 재확인 요청.
- FR-SPLIT-04 [P1] 정산 결과는 '누가 누구에게 얼마'의 검토용 내역이며 실제 송금 기능은 제공하지 않음.

### 4.5 공동 여행과 동기화

- FR-COL-01 [P2] 로컬 이용은 계정 필수 아님. 공동 여행을 시작하는 시점에만 로그인/가입을 유도.
- FR-COL-02 [P2] 소유자는 초대 생성·취소, 동행자 열람/편집 역할 지정, 제거. 사용자는 초대 수락/거절/탈퇴 가능.
- FR-COL-03 [P2] 역할별 권한: 소유자(전체 변경+역할/삭제), 편집자(공유 일정·장소·지출·자료의 생성/수정), 열람자(조회만).
- FR-COL-04 [P2] 서버의 권한 검증이 최종 기준. 클라이언트에서 버튼 숨김만으로 권한을 대체하지 않음.
- FR-COL-05 [P2] 편집 이력은 수정자·시각·대상·이전/변경 요약을 보유하고, 민감한 예약번호·원본 문서는 로그에 저장하지 않음.
- FR-SYNC-01 [P2] 오프라인에서는 로컬 데이터 읽기/쓰기. 온라인 복귀 후 미전송 변경을 동기화하고 '대기/동기화 중/완료/충돌' 상태 표시.
- FR-SYNC-02 [P2] 동일 객체 상충 편집은 사용자에게 차이를 보여주고 내 변경/서버 변경 중 선택. 자동 병합 가능 항목만 제한적으로 병합하고 데이터 유실 없이 원본 보존.
- FR-SYNC-03 [P2] 초대 취소·권한 박탈 시 서버 요청 차단, 로컬 열람 데이터 제거/보관 정책에 따라 처리. 권한 우회 방지 검증 필수.

### 4.6 여행 중 모드·기록·리포트

- FR-LIVE-01 [P3] 현지 날짜 기준 오늘 일정, 다음 일정, 수동 방문 상태, 중요 예약 요약 및 빠른 지출 추가 제공.
- FR-LIVE-02 [P3] 사용자의 체크인 버튼으로 방문 일시·대상·메모 생성. 별도 동의 없는 상시 위치 추적/자동 체크인 없음.
- FR-LIVE-03 [P3] 지연·순서 변경은 일정 편집 흐름과 연결하고, 실제 방문 기록과 계획 데이터는 별도 유지.
- FR-MEM-01 [P3] 방문 기록에 사진 여러 장·설명·촬영/추가 시각을 연결. 삭제 시 연결된 실제 방문을 자동 삭제하지 않음.
- FR-MEM-02 [P3] 날짜 및 장소별 기록 타임라인 제공. 방문 장소가 없는 사진도 '연결하지 않은 기록'으로 보존 가능.
- FR-REP-01 [P3] 계획 대비 실제 방문 개수·여행 날짜·지출 내역·대표 사진 등을 한 화면에 요약.
- FR-REP-02 [P3] 개인 보관이 기본. 공유 시 선택한 정보만 포함하며 예약번호·멤버 개인정보는 기본 제외.

### 4.7 AI·OCR (명시적 선택 기능)

- FR-AI-01 [P4] 취향, 날짜, 이동 제약 등 사용자가 제공한 조건으로 일정 후보를 생성. 출처·미확인 정보·AI 생성임을 구분.
- FR-AI-02 [P4] 기존 일정과 후보의 차이를 미리보기하고 사용자가 승인한 항목만 저장. 전체 자동 덮어쓰기 금지.
- FR-AI-03 [P4] 방문 기록을 토대로 여행 일기 초안을 생성하되 원본 사진·메모 삭제 또는 외부 공개 금지.
- FR-OCR-01 [P4] 사용자가 선택한 영수증 파일을 인식하여 금액·통화·날짜·상호 후보를 보여주고 저장 전 수정 가능.
- FR-AI-04 [P4] 서버 전송이 필요한 AI 요청에서는 전송 범위·비용/사용량 정책 안내 및 명시적 동의 제공.

### 4.8 설정·저장·알림

- FR-SET-01 [P0] 라이트/다크/시스템 테마, 기본 시간대·통화 설정. 여행 고유 시간대/통화는 여행 설정 우선.
- FR-SET-02 [P0] 필수 데이터는 앱 재실행·비행기 모드 전환 후에도 로컬에서 조회/수정 가능.
- FR-BACKUP-01 [P0] 기본 백업/복원 사양: 사용자 선택 파일로 구조화 데이터 내보내기·가져오기, 버전 검사, 미지원 파일 오류, 기존 여행 덮어쓰기 전 확인. 초기 구현 단계에서 실제 백업 범위와 파일 형식을 테스트로 확정.
- FR-BACKUP-02 [P1 이후] 사진·문서를 포함한 전체 보관/복구는 첨부 저장 방식이 확정된 단계에서 구현·검증.
- FR-SET-03 [P1 이후] 알림은 사용자가 기능 활성화 후 필요 시에만 권한 요청. 거부해도 일정 기능 사용 가능.

## 5. 업무 규칙 (BR)

- BR-01 시간대: 여행의 기준 시간대는 IANA ZoneId; 일정은 여행 날짜와 로컬 시각을 저장해 현지 날짜가 기기 시간대 변경으로 밀리지 않게 함. 체크인 등 실제 발생 시각은 UTC timestamp 별도 보존.
- BR-02 일정 충돌: 시간이 지정된 동일 날짜 항목끼리 겹침을 경고. 겹침이 있다고 저장을 막지 않음.
- BR-03 날짜 변경: 일정이 여행 기간 밖으로 이동하면 저장 전 경고 및 기간 조정 안내. 데이터의 조용한 삭제 금지.
- BR-04 통화: ISO 통화 코드와 통화별 최소 단위 사용. KRW 기본 소수 자릿수 0, 단 다른 통화는 통화 정의를 따름.
- BR-05 환율: 지출별 환율 및 기준일을 저장하고, 과거 정산액이 새로운 환율로 묵시적 변경되지 않음.
- BR-06 지출 음수 금지: 환불 처리는 원거래와 연결되는 별도 유형으로 향후 설계. P0는 일반 지출만 입력.
- BR-07 분담: 균등/지정금액/비율이 정확히 합계와 일치해야 확정; 반올림 잔액 정책은 UI에 표시.
- BR-08 로컬/공유: 처음 로컬 여행과 이후 클라우드 여행을 구분, 공유 전 동기화 범위·권한을 명시적으로 승인.
- BR-09 영구 삭제: 사용자 확인 전 다른 참가자의 데이터에 영향을 줄 범위를 고지. 소유자만 공유 여행 자체 삭제 가능.
- BR-10 '완료' 정의: 날짜 지남 = 종료된 여행 분류. 실제 방문 완료와 동일시하지 않음.
- BR-11 권한: 소유자·편집자·열람자는 서버 검증 기준; 권한 변경은 오프라인에서 임의 확정 불가.
- BR-12 오프라인: 지도 검색/경로/공동 초대/AI 요청은 네트워크 의존. 로컬 일정·장소 메모·경비·준비물은 사용 가능.

| 엔터티 | 핵심 필드 | 관계/제약 |
| --- | --- | --- |
| Trip | id, title, startDate, endDate, zoneId, baseCurrency, destination, description, ownerId? | 최상위 단위, 로컬 UUID |
| TripMember | tripId, userId, role, inviteStatus | P2, 복합 고유 키 |
| ItineraryDay | id, tripId, localDate, sortOrder | 여행 날짜별 |
| ItineraryItem | id, dayId, title, placeId?, startLocalTime?, endLocalTime?, sortOrder, note, priority, state | 시간 미정 허용 |
| Place | id, tripId, name, address?, lat?, lng?, provider?, providerPlaceId?, note? | 여행 내부 장소 참조 |
| ChecklistItem | id, tripId, title, isDone, sortOrder | P0 신규 추가 |
| Expense | id, tripId, amountDecimal, currencyCode, occurredAt, category, payerId?, note, rateSnapshot? | 금액 양수, 환율 스냅샷 |
| ExpenseShare | id, expenseId, memberId, amountDecimal, settledAt? | P1, 정확한 분담 합계 |
| Booking | id, tripId, type, title, referenceNumber?, startAt?, note? | P1 |
| Attachment | id, ownerEntityType, ownerEntityId, localUriOrPath, mimeType, status | P1, 파일 연결 관리 |
| VisitRecord | id, tripId, placeId?, itineraryItemId?, visitedAtUtc, note? | P3, 실제 방문 |

모든 엔터티는 ID 및 변경 시각을 가지며, 로컬 DB 변경은 트랜잭션으로 처리한다. 외래 키 참조 삭제 정책을 데이터 모델 구현 전에 정한다. UI는 Room을 포함한 로컬 저장소를 읽는 Repository를 데이터 진실원(source of truth)으로 이용한다. 클라우드 도입 시 서버 데이터와 버전 정보를 조정하되 화면에서 네트워크 응답을 직접 원본으로 삼지 않는다.

## 7. 기술·외부 서비스 결정

- UI: Kotlin + Jetpack Compose + Material 3.
- 구조: MVVM, 단방향 상태 흐름, Repository/Domain/Data 분리.
- 오프라인: Room 기본 데이터, DataStore 설정, Coroutines/Flow, 재시도 작업에 WorkManager.
- 지도: 외부 공급자 미확정. 평가 기준은 국내·해외 지도 커버리지, 장소 검색·경로, SDK 품질, 데이터 저장 라이선스, Android 비용·쿼터 및 장애 대응. 3단계 구현 전 PoC 후 공급자 1개 선정.
- 공동 여행: 인증/원격 데이터 저장 공급자는 4단계 이전에 선정. Firebase Auth/Firestore가 검토 후보이고 확정/도입 완료가 아님.
- 파일: Android Photo Picker 및 Storage Access Framework 활용. P1 이후 파일 접근 권한의 유지·복사 및 삭제 정책 검증.
- AI/OCR: 초기 설치에 AI 모델 강제 포함하지 않음. 온디바이스/서버 비용·개인정보 검토 후 채택.
- CI: GitHub Actions의 빌드→테스트→결과물 검증. Google Play 내부/비공개 테스트 자동 업로드는 별도의 사용자 승인 및 자격 요건 검증 후 도입.
- 공용 원칙: 키/토큰/서명 파일은 소스·로그에 저장하지 않는다.

기술 결정 게이트:
G-01 1단계 전: minSdk/targetSdk, 패키지명, 로컬 백업 포맷, DB 마이그레이션 규칙.
G-02 3단계 전: 지도 서비스 및 Maps/Places/Routes별 월간 쿼터·비용 알림.
G-03 4단계 전: 인증 공급자, 공유 보안 규칙, 충돌 정책, 사용자 탈퇴 시 데이터 소유권.
G-04 5단계 전: 첨부 파일 저장 위치, 파일 크기/개수 상한, 백업·데이터 삭제.
G-05 6단계 전: AI 전송 동의 문구, 데이터 보존 정책, API 비용·오작동 대응.

## 8. 사용자 인터페이스·접근성 기준

- 디자인 콘셉트: Travel Editorial. 정보·지도·사진 중심의 절제된 UI. 라이트/다크/시스템 테마.
- IA: 홈의 여행 목록 → 여행 작업 공간 → 날짜별 일정, 지도, 경비, 준비물, 예약, 참가자, 기록으로 맥락 이동.
- 표시 형태: 휴대폰 좁은 화면은 단일 컬럼, 태블릿/폴더블 넓은 화면은 목록·상세/지도 병렬 표시를 검토.
- 접근성: 글꼴 크기 160%에서 주요 버튼 잘림·수평 오버플로우 없음. 의미 있는 접근성 라벨과 터치 영역, 색상 외 텍스트/아이콘으로 상태 구분.
- 로딩/빈 상태/오프라인/오류/권한 거부/삭제 확인/저장 실패에 대한 화면을 필수 작성.
- 일정 삭제·정산·AI 반영 등 되돌리기 어려운 동작에는 영향 범위 확인 및 가능한 경우 실행 취소 제공.
- 자동 저장 여부는 화면 단위로 명시: 입력 폼은 '저장' 버튼으로 확정, 드래그·체크 전환은 즉시 로컬 커밋 후 취소 가능하게 설계.

## 9. 개인정보·보안

1. 사진·문서는 사용자가 선택한 항목만 접근하고 기능 사용 시점에 선택기를 호출한다.
2. 자동 위치 기록은 비활성. 지도 탐색에 현재 위치가 필요한 경우 그 시점에만 동의를 요청하고 거부해도 장소 수동 등록 지원.
3. 예약번호, 참가자 연락처, 첨부 원본/경로는 앱 로그·분석 이벤트·공개 공유 이미지에 포함하지 않는다.
4. 공동 여행은 서버 측 소유권/멤버십 검증과 초대 만료·취소·탈퇴 흐름을 구현한다.
5. 클라우드 백업·공유 전 데이터 범위·삭제 영향 안내. 계정 삭제 요청 처리와 데이터 내보내기 제공 범위 문서화.
6. 앱 파일·DB의 백업 정책, 미디어 파일 권한 및 암호화 정책은 구현 전 위협 모델링에서 확정한다.

## 10. 비기능 요구사항 (NFR)

- NFR-01 정합성: 앱 강제 종료/재시작/기기 재부팅 후 확정 저장된 데이터 소실 없음. DB 마이그레이션 테스트 필수.
- NFR-02 오프라인: 비행기 모드에서 여행 목록, 일정, 수동 장소, 체크리스트, 기본 지출 생성·수정·조회 가능.
- NFR-03 성능 목표: 여행 목록과 날짜 이동의 체감 지연 최소화. 구체 수치/기기 기준은 1단계 베이스라인 측정 뒤 확정(근거 없는 목표값 선언 방지).
- NFR-04 접근성: 화면 회전/작은 화면/태블릿·폴더블/글꼴 160%/스크린리더 기본 시나리오 검증.
- NFR-05 장애 복원력: 외부 API 오류·연결 끊김 시 로컬 사용자 데이터가 보존되고 재시도 또는 대안을 제공.
- NFR-06 프라이버시: 필요 최소 권한, 민감정보 로그 노출 0건, 공유 자료 비공개 기본값.
- NFR-07 테스트: 도메인 규칙 단위 테스트, DB 저장·복구 통합 테스트, 주요 화면 UI 테스트, CI에 최소 품질 검사.
- NFR-08 비용: 지도·AI·클라우드 도입 시 항목별 무료 할당/유료 과금/최대 월 예산·쿼터를 확인하고 초과 대응 정의.

# UI-A01 — 홈·여행 작업 공간 정보 밀도 개선

- 기준: 2026-11-12, main `ead5f6e74709a2bfeb4a9d419b44acbe1ce3c1ed`
- Google Drive 참고: [UI-R00 목표 시안·실제 Android 8종 비교](https://drive.google.com/drive/folders/1JLtNkO438c_APpeXcia46-g6lIzz5NJI)
- 관련 화면: S01 홈/여행 목록, S03 여행 작업 공간.
- 사용자 목표: 기능은 그대로 유지하며 모바일 첫 화면에서 여행 정보와 일정·경비·준비물·지도 진입을 더 빨리 찾도록 개선.

## 구현

1. `HomeScreen.kt`
   - 홈 상단 안내 문구 간결화.
   - 여행 카드 패딩 16→12dp, 내부 간격 8→4dp로 조정.
   - 여행 이름 → 목적지 → 여행 기간 → 상태·D-day 순서 유지, 실제 여행 ID/날짜/필터/편집/삭제 변경 없음.
2. `TripWorkspaceScreen.kt`
   - 여행 시간대·통화와 설명 보기/접기 컨트롤을 같은 수평 행에 배치. 설명 내용 및 상태 저장 유지.
   - 모바일 3종 요약의 카드 내 항목 간격 12→8dp; 다음 일정, 예산 대비 사용액, 미환산 외화, 준비물 상태 원문 계산·정보 보존.
   - 핵심 기능 **일정·경비·준비물·지도** 4종을 모바일 2×2 빠른 진입으로 구성. 긴 보조설명은 2줄까지 표시하며 카드 전체를 선택 가능하게 유지.
   - 태블릿/넓은 화면 기존 2열 카드·3열 요약 및 나머지 4종(예약·동행자 정산·동행자·저장 장소)의 진입 동선 변경 없음. 기존 접근성 설명과 최소 48dp 터치 유지.
3. `TripCanvas2CScreenshotTest.kt`
   - 실제 API35 기기 초기 작업 공간에서 스크롤 없이 **일정 열기**·**경비 열기** UIAutomator 접근성 대상 확인.
   - 최초 빠른 실행 화면 PNG 추가. 기존 홈 필터·CRUD·8개 기능 카드·요약·라이트/다크·160% 글꼴·SAF 백업 회귀 그대로 실행.

## 범위와 안전 조건

- 신규 기능/네트워크/의존성, Room/Repository/금액·환율·정산 계산, 테마/지도/예약, 설정/백업, 개인정보·Play 트랙 변경 없음.
- 실제 Android UI 화면 QA는 휴대전화·태블릿 각 API 35 라이트/다크·글꼴 160%와 UIAutomator 흐름을 통과해야 함. 앱 UI에서 제목·값·버튼 잘림이나 중첩이 보이면 수정 후 재실행.
- PR은 정확한 HEAD의 Android 빌드·JVM·Room 계측, 2-C phone/tablet, 3-A 지도, 3-B 경비/예약, API 29/36 호환성 CI를 확인한 뒤에만 안전 병합.
- 물리 폴더블, TalkBack 직접 사용, Google Play 심사/테스터 설치는 별도 검증. CI 성공으로 실기기 검증 완료를 주장하지 않음.
- `main` 병합은 기존 `play-internal.yml`에 의해 새 내부 테스트 AAB 업로드를 유발할 수 있음. 비공개 테스트(Alpha) 승격은 본 UI 변경의 자동 승인 범위가 아니며 기존 v10 심사 중 상태를 강제 변경하지 않음.

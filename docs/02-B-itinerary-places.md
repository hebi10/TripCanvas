# TripCanvas — 2-B 여행 일정·장소 관리

- 구현 범위: S04 날짜별 일정, S05 일정 생성/편집, S06 장소 저장·선택·편집
- 기준일: 2026-11-09
- 선행: [0-A 요구사항](./00-A-product-requirements.md), [0-B 화면 명세](./00-B-screen-spec.md), [2-A 여행 관리](./02-A-trip-management.md)
- 주의: P1 지도·장소 공급자 검색, P2 실시간 협업, P3 체크인, 2-C 경비·준비물은 범위 외입니다.

## 1. 데이터 모델과 로컬 보존

기존 Room DB 파일 tripcanvas.db를 유지한 채 버전 1 → 2 수동 Migration을 등록했습니다. destructive migration은 사용하지 않습니다.

- trips 기존 테이블과 사용자 입력은 그대로 유지합니다.
- places: UUID ID, tripId, 이름, 주소/메모, 선택적 위·경도, 생성/수정 시각. 여행 삭제 시 CASCADE.
- itinerary_items: UUID ID, tripId, 여행 현지 날짜(ISO LocalDate), 제목, 시작·종료시각(HH:mm 또는 둘 다 NULL), 선택 placeId, 메모, 중요/확정, 정렬 순서, 생성/수정 시각.
- itinerary_items.tripId는 여행 삭제 시 CASCADE, placeId는 장소 삭제 시 SET NULL입니다. 따라서 장소를 삭제해도 관련 일정은 남습니다.
- 모든 조회·수정·삭제는 tripId와 항목 ID로 제한하고, 다른 여행의 장소가 연결되지 않도록 Repository에서 검증합니다.
- 여행 일자/현지 시각은 UTC 타임스탬프로 변환하지 않고 로컬 값으로 저장합니다. 기기 시간대 변경으로 입력 일자가 하루씩 밀리지 않습니다.

## 2. S04 날짜별 일정 타임라인

- 현재 여행의 시작·종료 날짜 안에서 이전/다음 날짜 및 날짜 칩, 날짜 바로 이동을 제공합니다.
- 시간 지정 일정과 시간 미정 일정을 별도 구역으로 표시하고, 중요·확정·시간 겹침 상태를 표시합니다.
- 항목 수정, 복제, 삭제, 길게 누르는 이동 핸들, 위/아래 재정렬을 제공합니다.
- sortOrder를 Room에 저장하므로 앱 재실행 후에도 같은 날짜·그룹 내 사용자 순서가 유지됩니다.
- 삭제 전 확인 및 저장/로드 오류 안내를 제공합니다.

## 3. S05 일정 추가·편집

- 필수: 제목(공백 제거 후 1~100자), 여행 기간 안의 날짜.
- 선택: 시작/종료 시각(HH:mm 모두 입력 또는 모두 비움), 장소, 메모(최대 2,000자), 중요 표시, 확정 표시.
- 종료 시각이 시작보다 빠르면 저장을 차단합니다. 서로 다른 시간 지정 일정이 겹치면 충돌 개수와 함께 경고를 표시하고 '그래도 저장'을 사용자가 선택하도록 합니다.
- 날짜 이동은 여행 기간 범위 안에서 허용합니다. 기간 밖 날짜는 필드 오류로 차단합니다.
- 복제는 새 UUID를 부여하고 원본 ID/별도 기록을 복제하지 않습니다.
- 저장 실패 시 입력값 유지, 중복 제출 방지, 미저장 변경 뒤로가기 경고를 적용합니다.
- 시간 미정 항목은 startTime/endTime 둘 다 NULL로 저장합니다.

## 4. S06 수동 장소 관리

- 장소 이름(1~100자) 필수, 주소·메모·위경도는 선택입니다.
- 좌표는 함께 입력할 때 위도 -90~90, 경도 -180~180을 검사합니다.
- 여행별 장소 목록, 이름/주소/메모 검색, 신규 장소, 편집, 삭제를 지원합니다.
- 장소 선택은 일정 편집 화면으로 장소 ID를 전달합니다.
- 외부 지도/검색 API가 없어도 수동 장소 생성·연결이 가능합니다.
- 장소 삭제 전 해당 장소가 연결된 일정 개수를 보여주고, 삭제 후 일정 자체는 남으며 장소 연결만 해제됩니다.

## 5. 2-A 여행 기간 변경 보호

- 여행 시작일/종료일을 변경할 때 기존 일정 중 변경 기간 밖에 놓일 항목이 있는지 조회합니다.
- 1건 이상이면 변경 자체를 차단하고 개수/날짜를 표시해 일정 이동·삭제 후 다시 시도하도록 안내합니다.
- 범위 밖 일정은 자동 삭제하지 않습니다. 시간대 변경은 일정의 로컬 날짜/시각 문자열을 수정하지 않습니다.
- 여행 삭제 시 기존 확인 문구에 일정·저장 장소 동시 삭제 사실을 추가했습니다.

## 6. 구조

- data/local: TripDatabase(v2), TripDao, PlaceDao, ItineraryDao, PlaceEntity, ItineraryItemEntity
- data: TripRepository, PlaceRepository, ItineraryRepository
- domain: TripRules, PlaceRules, ScheduleRules
- screens: TripDayScreen, ScheduleFormScreen, PlaceListScreen, PlaceFormScreen
- navigation: TripDestinations 및 TripApp 경로 확장. 별도 로그인·클라우드 의존성 없음.

## 7. 자동 및 수동 검증

CI: GitHub Actions에서 Debug APK 빌드 및 JVM 단위 테스트를 실행합니다.

단위 테스트:
- 일정 날짜·시각·중복 시간 판정, 메모 및 필수 제목 검증
- 위경도 범위/누락 검사, 좌표 없는 장소 저장
- 저장소의 생성·수정·삭제·복제, 같은 시간 겹침 승인, 정렬 순서 저장
- 다른 여행 장소 연결/일정 조회 차단
- 여행 기간 밖 일정이 존재하는 경우 기간 변경 거부

실기기 검증으로 남겨둔 항목:
- 2-A DB에 이미 여행이 있는 기기에서 Room v1→v2 업그레이드 후 기존 여행 보존, 새 장소/일정 저장과 앱 재실행
- 작은 화면·160% 폰트·다크/라이트·폴더블·태블릿, 장기 여행 날짜 탐색
- 드래그 재정렬 및 TalkBack, 날짜 선택기/IME, 저장/삭제 도중 화면 전환, 장소 삭제 후 연결 해제
- Android API 29/35/36 계측, Google Play 비공개 테스트 배포 및 스토어 이미지 (추후 별도 단계)

# TripCanvas — 2-C 준비물·경비 및 백업·복원

- 기준일: 2026-11-09
- 선행: [0-A 기능 요구사항](./00-A-product-requirements.md), [0-B 화면 명세](./00-B-screen-spec.md), [2-B 일정·장소](./02-B-itinerary-places.md)
- 범위: S09 기본 예산·경비, S10 지출 생성·편집, S12 준비물, S20 파일 백업·복원
- 디자인: 기존 Travel Editorial 테마·컴포넌트·단일 수직 스크롤 구조를 유지합니다.

## 1. Room v3 및 데이터 보존

- 기존 DB 파일 \`tripcanvas.db\`와 여행·장소·일정 테이블을 유지하며, Room v2→v3 수동 Migration을 추가했습니다.
- 기존 v1 DB는 \`MIGRATION_1_2\` → \`MIGRATION_2_3\` 순서로 올라갑니다. \`fallbackToDestructiveMigration\`은 사용하지 않습니다.
- \`checklist_items\`: UUID, tripId, 이름, 체크 여부, 정렬 순서, 생성·수정 시각.
- \`expenses\`: UUID, tripId, 금액 문자열, ISO 4217 통화, 현지 지출 일시, 분류, 메모, 선택 placeId, 생성·수정 시각.
- \`trip_budgets\`: 여행 ID별 선택적 총예산, 통화 코드, 십진 문자열 금액.
- 여행 삭제 시 연결 데이터 CASCADE, 장소만 삭제하면 기존 일정·지출의 placeId만 SET NULL 처리합니다.
- 모든 지출·준비물 조회와 변경은 여행 ID로 범위를 제한합니다.

## 2. 준비물 화면 S12

- 준비물 이름 1~100자 생성·수정·삭제, 완료 체크 토글, 완료 개수/전체 개수 표시.
- 전체/미완료 필터, 수동 위·아래 순서 변경. 위치는 DB에 저장되어 재실행해도 유지됩니다.
- 삭제 전 확인 후, 화면에 남아 있는 동안 방금 삭제한 항목의 상태·이름·ID를 복구할 수 있습니다.
- 체크 완료 항목은 자동 삭제하지 않고, 체크 해제도 가능합니다.
- 로컬 저장 오류 안내·재시도, 버튼 중복 요청 방지.

## 3. 예산·경비 화면 S09/S10

- 총예산은 여행 기본 통화로 선택 저장·변경·해제 가능.
- 지출: 0 초과 금액, 통화, 날짜, 현지 시간, 식비/교통/숙박/관광/쇼핑/기타 분류, 메모(최대 2,000자), 선택적 저장 장소.
- 각 여행의 지출 CRUD, 날짜별 내역, 삭제 확인 및 입력값 보존.
- 금액 연산은 \`BigDecimal\`을 사용하며, 통화별 최소 자릿수(예: KRW 0, USD 2, KWD 3)와 소수점 정확도를 검증합니다.
- 지출 현지 시각은 \`yyyy-MM-dd'T'HH:mm:ss\`로 저장합니다. 선결제 등 여행 기간 외 날짜도 허용합니다.
- 여행 기본 통화와 같은 지출만 예산 대비 합계에 포함합니다.
- 다른 통화의 지출은 통화별 '환산 필요'로 별도 표시하고, 확인되지 않은 환율로 합산하지 않습니다.
- 여행 기본 통화가 변경돼 이전 총예산과 달라지면 자동 환산하지 않고 비교 불가를 표시합니다.
- 통화 환산 스냅샷, 참가자 정산·영수증 첨부는 P1/3-B 단계에서 구현합니다.

## 4. JSON 백업·복원 S20

### 백업 파일 형식

- 파일명 기본값: \`TripCanvas_backup_YYYY-MM-DD.json\`, UTF-8, JSON, \`format=tripcanvas-structured-backup\`, \`version=1\`.
- 포함: trips, places, itineraries, expenses, budgets, checklist. Room 스키마와 별개로 백업 포맷 버전을 관리합니다.
- 포함하지 않음: 테마/온보딩 DataStore, 향후 사진·첨부 파일, 계정·클라우드 데이터.
- 최대 JSON 크기 10MB. 이 범위를 넘는 데이터는 명확한 오류로 처리합니다.
- 기본 JSON 파일은 **암호화되지 않습니다**. 여행 메모·경비·장소 등 개인정보가 포함될 수 있으므로 안전한 위치에 보관해야 합니다.
- 서버에 업로드하지 않으며 Android SAF 문서 선택기 \`CreateDocument\`/\`OpenDocument\`를 사용합니다.

### 복원

1. 사용자가 직접 JSON 파일을 선택합니다.
2. 최대 크기·UTF-8·포맷/버전·필수 필드·중복 ID·여행 소유 관계·참조 무결성·금액/시간대/날짜 등을 사전 검증합니다.
3. 기존 기기 여행 수와 복원 파일 여행/장소/일정/경비/예산/준비물 개수를 미리 보여줍니다.
4. **기존 데이터를 전체 교체**한다는 명시적 확인이 있어야 복원합니다. 기존 데이터와 병합하거나 조용히 덮어쓰지 않습니다.
5. Room \`@Transaction\`으로 전체 교체하여 입력/제약 조건 오류 시 기존 자료로 롤백합니다.

백업·복원은 사용자 선택한 로컬 파일만 대상으로 하며, 기기 외부 자동 동기화나 주기 예약은 포함하지 않습니다.

## 5. 검증 및 남은 QA

- Android Debug 빌드 및 JVM 테스트: 통화 정밀도, 금액 0/음수/과도한 소수점, 미환산 합계 분리, 지출 현지 일시 검증, 준비물 CRUD·토글·정렬·삭제 복원.
- API 35 에뮬레이터: 기존 Room v1→v3, v2→v3 데이터 보존과 FK 처리.
- Android 계측 테스트: JSON 6개 엔터티 왕복 복원, 미지원 버전/참조 오류 차단, 복원 중 삽입 오류 시 트랜잭션 롤백.
- 실제 Android 화면/접근성 QA는 별도: 작은 화면, 160% 글꼴, 라이트·다크, 폴더블/태블릿, 회전·키보드, 비행기 모드 및 앱 재실행.
- 10MB 초과 백업·저장소 권한 거부·외부 제공자 오류 및 대량 데이터 성능은 추가 실측이 필요합니다.
- AAB 서명과 Google Play 비공개 테스트 배포는 이번 기능 PR에 포함하지 않습니다.

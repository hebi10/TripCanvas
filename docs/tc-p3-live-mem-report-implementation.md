# TC-P3 LIVE-01 → MEM-01 → REPORT-01

## 구현 범위
- `LIVE-01`: 여행 시간대 기준 현지 오늘 날짜의 일정·다음 일정·예약명과 예약 시각(확인번호 제외), 수동 체크인과 방문 메모, 빠른 지출/기록 진입.
- `MEM-01`: 실제 방문 시각(UTC)과 일정 제목의 스냅샷 저장, 사용자가 고른 사진의 SAF content URI 및 메모 저장. 사용자가 방문을 선택하지 않으면 미연결 기록으로 남는다. 원본 파일은 이동/삭제하지 않는다.
- `REPORT-01`: 일정 수, 실제 방문 수, 메모/사진 수, 첫 사진의 미리보기, 기본 통화에 환산된 지출액만 요약. 미환산 외화 제외 안내.
- 진입점: 여행 작업 공간의 '오늘의 여행', '여행 기록', '여행 리포트' 3종. 로컬 Room 데이터 기반.
- 방문 기록은 기존 일정의 삭제와 독립적으로 보존하고, 여행 삭제 시 관련 기록은 여행 데이터와 함께 삭제한다. 동일 일정에 대한 중복 체크인은 DB 유니크 인덱스로 방지.

## DB/백업
- Room v5→v6 비파괴 마이그레이션. 기존 v1~v4 데이터베이스에서 v6까지 연결되는 경로를 회귀 검증한다.
- JSON 백업 형식 v4는 방문·사진 **메타데이터**를 백업한다. 기존 v1~v3 백업은 빈 방문/사진 기록으로 복원한다.
- 사진 원본 바이트는 JSON 백업 대상이 아니다. 같은 기기에서 원본 URI의 읽기 권한을 지속하려고 시도하지만, 파일 삭제·이동 또는 다른 기기로 복원한 경우 URI가 무효일 수 있다. 해당 경우 기록 메타데이터는 유지하지만 사진은 열리지 않을 수 있다.
- 향후 사진 원본 내보내기·기기 간 완전 복구는 별도 설계/검증이 필요하다.

## 프라이버시
- 자동 위치 추적, 자동 사진 스캔, 외부 AI·클라우드 전송 없음.
- 여행·지출·예약 자료는 로컬 저장. 오늘 예약 요약에는 확인번호를 노출하지 않는다.
- 원본 사진의 복사·변환·삭제 없음.
- 민감한 예약·참가자 정보가 리포트/공유 데이터에 자동 포함되지 않는다. 공유/내보내기는 별도 후속 기능이다.

## QA와 한계
- Android/Room DB 마이그레이션과 JSON 백업 round-trip, 중복 체크인 및 기존 일정 보존 검사.
- Android 화면 캡처와 폰/태블릿 160~200% 글꼴, 사진 파일 제공자 변경·권한 소실, 오프라인, 폴더블, Play 테스터 실제 설치는 별도 실행 증빙 필요.
- 외부 파일/실기기 최종 검증을 하지 않은 코드 작업은 최종 PASS로 처리하지 않는다.
- `[skip-play]` 유지: Play AAB 업로드, 스토어 변경, 트랙 승격 없음.

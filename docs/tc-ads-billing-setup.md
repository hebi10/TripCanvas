# TC-ADS-01 — 광고 및 광고 제거 구독

## 범위
- 홈 화면 하단에만 AdMob 배너 광고 준비. 여행 편집/지도/예약/지출/정산/파일 작업 화면에는 광고 없음.
- UMP 동의 업데이트 후 `canRequestAds()`가 참이고 Google Play 구독 조회가 완료되었으며 광고 제거 구독이 없는 경우에만 광고를 요청한다.
- Google Play Billing Library 9.1.0을 사용한 정기 결제 상품 조회/구매/복원/구매 승인 흐름.
- 이번 PR은 별도 기능 브랜치이며 `[skip-play]` 유지. Google Play 상품 생성/실제 구매/AAB 배포 없음.

## Play Console 상품 생성 명세
- 구독 상품 ID: `tripcanvas_ad_free`
- 자동 갱신 기본 요금제 ID: `monthly`, 월 1,000원(KRW)
- 자동 갱신 기본 요금제 ID: `yearly`, 연 9,900원(KRW)
- 기본 혜택: 사용자의 활성 기간 동안 앱 홈 배너 광고 제거. 기존 여행·일정·백업 데이터는 구독 상태와 무관하게 접근 가능.
- Play Console에서 상품 승인/활성화 전에는 해당 가격을 앱에서 하드코딩해 결제 버튼으로 보여주지 않는다. 구매 가능하고 대상 국가에 적합한 offerToken과 현지화된 가격을 조회하여 표시한다.
- 테스트는 Play 라이선스 테스터와 설치된 내부 테스트 앱에서만 수행한다. 실제 결제/환불은 별도 승인 없이는 수행하지 않는다.

## AdMob/UMP
- 빌드 환경 변수: `TRIPCANVAS_ADMOB_APP_ID`, `TRIPCANVAS_ADMOB_BANNER_ID`.
- 운영 ID가 없으면 광고 요청이 아예 발생하지 않는다. Gradle은 SDK manifest provider 무결성을 위해 Google 공식 예제 앱 ID를 사용하나, **공식 샘플을 운영 광고 ID로 사용하지 않는다**.
- ID가 올바른 형식인 경우에만 `ADS_CONFIGURED=true`. 테스트 기기에서 Google 공식 테스트 광고 단위로 확인하고 운영 출시 전 계정의 광고 단위 ID로 전환한다.
- UMP 광고 동의 요청: 앱 시작 시 업데이트. 지역에 따라 동의 양식을 표시하고 필요한 경우 설정에서 개인정보 선택 변경 제공.
- UMP 오류/동의 거부/Play 구매 상태 미확인 시 광고 요청 금지.
- 개인정보처리방침과 Play Console 데이터 보안·광고 선언의 실제 SDK 동작 정합성 재검토 필요.

## 보안·구독 수명
- `queryPurchasesAsync`를 앱 진입 및 복원 시 호출하여 현재 Play 구매 상태를 다시 조회한다.
- 구매 상태 `PURCHASED`와 초기 구매 승인 결과 확인. `PENDING` 결제는 광고 제거 권한을 부여하지 않는다.
- **현재 앱은 클라이언트 측 Play 응답만 처리합니다.** 최종 유료 운영 전에 서버측 Play Developer API 정기 결제 토큰 검증, 갱신/환불/철회/계정 전환/기기 간 복원·알림 검증을 구현해야 한다. 단순 기기 내 캐시를 신뢰하는 영구 광고 제거를 제공하지 않는다.
- Billing 연결 실패 시 결제 수단 정보를 앱에 보관하지 않으며 구독 상태를 알 수 없으면 광고를 로드하지 않는다.
- 백엔드 검증 전까지 실제 판매를 활성화하지 않는다.

## 출시 전 체크
1. 최신 main에 기존 P3 기능/백업 및 광고 PR 안전 병합, Android/Room/2-C/3-A/3-B/API29·35·36/OPS 정책 검사 성공.
2. AdMob 계정·앱/배너 ID 확보. 테스트 광고 ID/실제 광고 ID를 혼동하지 않기.
3. Google Play에 Billing permission 포함한 서명 AAB를 내부 테스트에 등록한 뒤, 구독 상품 및 2개 기본 요금제 등록.
4. 운영 서버 구매 검증과 광고 제거 권한 동기화 완료.
5. 라이선스 테스터로 월간/연간 구매, 보류, 취소, 갱신, 복원, 환불/철회, 동의 거부, 네트워크 실패 테스트.
6. 개인정보처리방침·데이터 보안·광고 선언·최종 스토어 정책 검증 완료 후 별도 승인 배포.

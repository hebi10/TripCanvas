# TC-FIX-02-B — 복원 전 안전 백업 (2026-11-25)

기준 main: 1775d09cf557b708b90d3693e8307cd54eae57c7. 기존 JSON v1~v4/.tcb 암호화 백업 포맷과 Room v6 스키마 유지.

## 구현 및 보존 범위
- 최종 사용자 승인 시 Room 트랜잭션 내부에서 현재 구조화 snapshot과 예약 첨부 연결 행을 수집한다. 기기 내부 안전 백업 저장 및 인증된 복호화 readback에 성공해야만 전체 교체를 수행한다.
- Android Keystore의 기기별 AES-256-GCM 키, 매번 새 IV, 인증 헤더 및 AtomicFile 사용. 최대 구조화 JSON 10MiB, 전체 checkpoint 16MiB. 평문 파일/비밀번호 저장, 서버 전송 없음.
- 복원 전 안전 백업은 최신 1개만 보존하고 안전 백업으로 복구할 때도 현재 상태를 새 안전 백업으로 저장한다. 저장 실패·검증 실패·용량 초과는 교체 전 차단하며 Room 교체 실패 시 트랜잭션이 롤백된다. 파일과 DB는 독립 저장소이므로 실패 시 안전 백업이 직전 현재 상태로 교체될 수는 있다.
- 복구 내용 미리 확인, 명시적 전체 교체 승인, 오래된 checkpoint 선택 거부, 안전 백업의 별도 삭제. 안전 백업은 앱의 noBackupFilesDir에 저장되며 앱 삭제/데이터 초기화 또는 키 분실 시 복구할 수 없다. 현재 여행 삭제만으로 과거 복구본이 삭제되지는 않는다.
- 예약 첨부 연결 행 및 방문·사진 메타데이터를 보존하나 원본 파일은 포함하지 않는다. 외부 제공자 권한이나 원본 파일이 사라지면 다시 연결해야 한다. 외부 백업 파일의 기존 예약 첨부 제외 정책 유지. 다음 TC-FIX-02-C에서 사진/PDF 원본 보존·이동을 다룬다.

## 검증
- A06 Android API35: 실제 Android Keystore/AtomicFile 암호화, 새 서비스 인스턴스 재조회, 이전 데이터 및 첨부 연결 복구, 최신 checkpoint 교체, 오래된 복구본·변조 거부, 삭제 후 현재 데이터 유지. 저장/재조회 실패의 DB 불변과 복구 도중 저장 실패 차단.
- 기존 JSON/.tcb 왕복 및 외부 첨부 제외 테스트 유지. Android 빌드/JVM/OPS 검사. 전체 UI·물리 기기·첨부 접근 권한 검증은 후속 최종 QA.
- 개인정보처리방침 및 Play 설명은 최종 승인 전 실제 백업 정책에 맞게 현행화할 것. 이 PR에서 Play 게시·웹 배포·외부 API 활성화 없음.

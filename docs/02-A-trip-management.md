# TripCanvas — 2-A 여행 생성·관리 구현

- 기준일: 2026-11-09
- 선행: [0-A 제품 요구사항](./00-A-product-requirements.md), [0-B 화면 명세](./00-B-screen-spec.md), [1-B 앱 탐색](./01-B-navigation-onboarding-settings.md)
- 구현 단계: 2-A / S01 홈 여행 목록 · S02 생성·편집 · S03 실제 여행 상세
- 2-B/2-C 일정·경비·준비물 저장소는 미구현. 지도·계정·동기화·배포 역시 범위 제외.

## 1. 저장소와 기술

- 기존 앱 ID \`com.hebi.tripcanvas\`, Kotlin/Compose/Material 3 기반 유지.
- Room 2.8.5, KSP 2.3.10, SQLite 파일 \`tripcanvas.db\`를 앱 전용 저장소에 사용.
- \`TripDatabase\` 스키마 버전 1. 기존 앱의 DataStore 온보딩/테마 설정과 별도 관리.
- \`TripDao\`: \`observeAll\`(시작일 순), \`observeById\`, \`findById\`, \`insert\`, \`update\`, \`deleteById\`.
- \`TripRepository\`: UUID 여행 ID 생성, 필수 입력 검증, 원본 ID·생성 시간 보존, 업데이트/삭제 대상 미존재 검출.
- 앱에서는 읽기 실패와 저장 실패를 별도 상태로 표시. 로컬 저장은 로그인·네트워크 권한이 필요 없다.
- 현재 스키마에 자식 일정·경비·준비물 데이터가 없으므로 기간 변경 시 자식 데이터 영향을 처리할 대상이 없다. 2-B/2-C에서 관련 엔터티 추가 시 기간 축소 검사를 함께 구현해야 한다.

## 2. Trip 데이터 필드

| 필드 | 설명 |
| --- | --- |
| id | 문자열 UUID, PK. 제목이 같아도 별도 여행 |
| title | 공백 제거 후 1~80자 |
| startDate / endDate | ISO LocalDate 문자열 YYYY-MM-DD, 종료일은 시작일 이후 또는 같은 날 |
| country / city | 선택값, 각각 80자 이내 |
| timeZoneId | IANA ZoneId, 예: Asia/Seoul |
| currencyCode | ISO 4217 대문자, 예: KRW |
| purpose | 선택값 120자 이내 |
| note | 선택값 2,000자 이내 |
| createdAtMillis / updatedAtMillis | UTC epoch ms, 수정 시 생성 시각 보존 |

- 여행 상태는 DB에 고정값으로 기록하지 않고 여행 시간대의 오늘 날짜를 기준으로 계산한다.
- 오늘 < 시작일: 예정, 시작일 ≤ 오늘 ≤ 종료일: 여행 중, 오늘 > 종료일: 완료.
- 일자가 지나도 여행 자체나 추후 일정은 자동 삭제하지 않는다.
- 새 여행 시작일/종료일은 기기 현지 날짜를 초기값으로 제안하며, 시간대와 통화는 기기 기본값을 제안한다. 사용자는 생성·편집 화면에서 직접 수정할 수 있다.

## 3. S01 홈

- 전체/예정/여행 중/완료 필터를 실제 Room Flow 목록에 연결.
- 카드에 제목, 날짜 범위, 현지 시간대, 국가/도시(설정했을 때), 상태, 출발까지 남은 일수 표시.
- 카드 선택 시 해당 여행 ID로 S03에 진입.
- 홈에서 편집/삭제 버튼 제공. 삭제 시 여행명 재입력 대화상자 표시.
- 여행이 없거나 필터 결과가 0건일 때 각각 다른 빈 상태 표시.
- 데이터 로드 실패 시 오류 안내·재시도.

## 4. S02 여행 생성·편집

- 제목, 날짜 범위, 국가/도시, 시간대, 통화, 여행 목적, 메모 입력.
- 날짜는 Compose Material DatePicker를 사용하여 날짜만 저장하고, UTC 날짜 선택 값을 한국 등 기기 시간대로 잘못 이동시키지 않음.
- 시간대/통화는 자주 쓰는 후보를 칩으로 선택하거나 직접 코드 입력.
- 필수값·길이·날짜 역전·ZoneId·ISO 통화 검증, 오류 이유를 입력부에 표시.
- 저장 중 반복 제출 차단, 저장 실패 시 현재 입력 보존.
- 시스템 뒤로가기/상단 뒤로가기로 미저장 변경을 떠날 때 명시적 폐기 확인.
- 신규 저장 성공 → 신규 S03으로 이동. 편집 성공 → 기존 화면으로 복귀.
- 대표 사진은 이번 단계에 첨부하지 않으며 후속 단계에서 추가.

## 5. S03 여행 상세

- 실제 \`tripId\`를 Room에서 로드하고 해당 여행의 제목, 기간, 목적지, 시간대/통화, 목적/메모를 표시.
- 해당 ID만 조회하기 때문에 같은 이름의 다른 여행이 섞이지 않는다.
- 상단 편집·삭제 동작 제공. 미존재/삭제된 ID는 안전한 빈 상태 표시.
- 일정·경비·준비물은 후속 단계 예정 문구만 표시하고 가짜 일정/지출/완료 수치를 표시하지 않는다.
- 1-B 설정에 있던 작업 공간 디자인 미리보기는 별도 유지한다.

## 6. 삭제 및 안전성

- 삭제 버튼을 누르면 영구 삭제 위험과 백업 미보유 시 복구 불가를 설명.
- 사용자가 정확한 여행명을 입력했을 때만 삭제 확인 버튼 활성화.
- 삭제는 \`tripId\`로 수행하므로 같은 이름의 다른 여행을 삭제하지 않음.
- 저장/삭제 실패는 숨기지 않고 대화상자와 폼에 오류를 표시.
- DB destructive migration(스키마 불일치 시 기존 DB 삭제) 옵션은 사용하지 않음.

## 7. 테스트·검증

- \`TripRulesTest\`: 제목 공백/길이, 날짜 역전, 잘못된 ZoneId/통화, 선택값, 현지 날짜 기준 상태 분류.
- \`TripRepositoryTest\`: 동일 제목의 별도 UUID, CRUD 보존·삭제, 무효 데이터 저장 차단.
- GitHub Actions: \`./gradlew :app:assembleDebug :app:testDebugUnitTest --stacktrace\`. PR의 모든 CI 작업이 성공해야 병합.
- 공식 빌드에 포함된 Room 스키마 v1 JSON의 버전 관리/이후 Migration 테스트는 다음 DB 변경 시 필수.
- 별도 실기기 QA: 첫 저장·재실행 복원, 삭제 후 재실행, 160% 폰트·다크·태블릿, 비행기 모드·ADB 재실행, DatePicker 타임존 경계, TalkBack, 앱 프로세스 종료 중 저장.

## 8. 후속 단계

- 2-B: 여행 ID에 연결된 일정·장소 Room 모델, CRUD 및 여행 기간 변경 시 자식 일정 영향 경고.
- 2-C: 경비·준비물·백업/복구를 추가하고 삭제 범위 및 이관 정책 갱신.
- 실기기 캡처, API 29/35/36 QA, AAB 서명·Google Play 테스트 트랙은 별도 출시 단계.

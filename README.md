# TripCanvas

> 여행을 계획하는 순간부터 돌아와 추억을 정리할 때까지, 하나의 캔버스에서 관리하는 Android 여행 앱.

**프로젝트 상태: 2-C 준비물·경비·백업·복원까지 `main` 병합 완료 / 병합 버전 자동 검증 진행**  
**플랫폼: Android 우선**  
**개발 방향: Kotlin + Jetpack Compose 기반 네이티브 앱 제안**  
이 문서는 제품 요구사항 및 개발 로드맵 초안입니다. 아래 기능은 구현 완료를 의미하지 않습니다.

## 1. 프로젝트 개요

TripCanvas는 **여행 일정 · 지도 · 공동 편집 · 경비 정산 · 예약 자료 · 현장 여행 모드 · 여행 기록**을 연결하는 여행 관리 애플리케이션입니다.

기존의 일정표와 지도, 메신저, 가계부, 사진 앨범 사이를 오가는 사용 경험을 하나의 여행 단위로 통합합니다. 단순 여행 추천보다 **실제 여행을 계획하고 실행하고 회고하는 과정**에 집중합니다.

### 주요 대상

- 혼자 자유여행을 계획하고 장소와 경비를 체계적으로 관리하려는 사용자
- 친구·연인·가족과 일정과 비용을 함께 정리하는 사용자
- 여행 후 사진·장소·이동 경로를 연결해 추억을 남기고 싶은 사용자

### 핵심 가치

1. **하나의 여행 공간**: 일정, 지도, 예산, 예약 자료, 기록을 같은 여행에 연결
2. **계획과 현실의 연결**: 예정한 일정을 현장에서 수정하고 실제 방문 기록으로 전환
3. **공동 여행 지원**: 참가자별 접근 권한, 변경 이력, 공유 지출과 정산
4. **명확한 사용자 통제**: AI가 제안한 일정·경로도 직접 검토·편집·삭제
5. **오프라인 우선**: 저장한 핵심 기록은 인터넷이 불안정해도 열람·편집 가능하도록 설계

## 2. 주요 기능 기획

| 영역 | 핵심 기능 | 상세 요구사항 |
| --- | --- | --- |
| 여행 프로젝트 | 여행 생성·관리 | 제목, 기간, 국가·도시, 여행 목적, 대표 이미지, 통화, 시간대, 참가자 |
| 여행 일정 | 일자별 일정 편집 | 시간표, 장소, 메모, 우선순위, 드래그 정렬, 복제, 변경·삭제, 일정 충돌 표시 |
| 장소·지도 | 여행 지도 | 장소 검색·저장, 핀, 일정과 지도 양방향 연동, 이동 수단별 경로 비교 |
| 여행 동선 | 경로 추천 | 날짜별 방문 순서 제안, 예상 이동 시간 및 중복 이동 점검, 사용자가 최종 확정 |
| 공동 여행 | 초대·역할·동기화 | 소유자/편집자/열람자, 초대 링크, 변경 기록, 편집 충돌 처리 |
| 예산·경비 | 여행 가계부 | 총예산, 카테고리, 결제자, 통화, 지출 내역, 영수증 첨부 |
| 정산 | 동행자별 비용 분담 | 균등·지정 금액·비율 분담, 개인 부담금, 정산 상태, 내역 수정 |
| 예약·준비 | 여행 문서 보관 | 항공·숙소·교통·입장권 정보, 확인번호, 첨부 파일, 준비물 체크리스트 |
| 여행 중 모드 | 오늘의 여행 | 다음 일정, 현재 진행 상태, 수동 체크인, 일정 지연·변경, 중요 정보 빠른 조회 |
| 여행 기록 | 여행 타임라인 | 방문 장소별 사진·메모·일시, 장소별 앨범, 실제 일정과 계획 비교 |
| 여행 리포트 | 여행 요약 | 방문 장소, 기록 사진, 실제 지출, 일정 진행, 공유 가능한 결과물 |
| AI 지원(선택) | 일정·동선 보조 | 취향과 제약에 따른 후보 생성, 동선 개선, 여행 일기 요약, 적용 전 사용자 승인 |

### 기능 설계 원칙

- 지도·장소·경로 데이터는 외부 API 연동 범위와 비용을 검토한 후 공급자를 결정합니다.
- 이동 시간·거리·운영 시간은 검증되지 않은 값을 임의로 확정해서 표시하지 않습니다.
- 실제 방문 기록은 기본적으로 **사용자 수동 체크인**을 사용합니다. 자동 위치 기록은 추후 명시적 동의를 받은 경우에만 추가합니다.
- AI는 제안과 요약을 담당하며 **예약, 결제, 일정 삭제, 공동 데이터 변경을 사용자 동의 없이 수행하지 않습니다.**
- OCR 영수증 인식·자동 다이어리 생성·실시간 협업은 기본 기능의 안정화 이후 단계적으로 구현합니다.

## 3. 핵심 사용자 흐름

### 여행 계획

1. 새 여행 생성 → 기간·목적지·참가자 설정
2. 장소 검색 및 저장 → 날짜별 일정으로 배치
3. 지도에서 위치·경로 확인 → 이동 및 시간 충돌 검토
4. 예산·준비물·예약 자료 등록 → 여행 전 체크리스트 확인

### 여행 중

1. 오늘 일정 열기 → 다음 장소와 예약 자료 확인
2. 방문 완료 체크인 → 필요 시 시간과 순서를 수정
3. 사용한 비용 입력 → 참가자별 지출 반영
4. 사진과 메모 추가 → 방문 장소 타임라인 축적

### 여행 종료

1. 실제 방문 장소·경비 검토
2. 동행자 비용 정산 확인
3. 사진·장소 기반 여행 리포트 생성
4. 개인 보관 또는 선택적으로 공유

## 6. 기술 및 아키텍처 제안

아래 구성은 **확정된 구현 결과가 아닌 개발 검토안**입니다.

| 영역 | 기술 후보 | 목적 |
| --- | --- | --- |
| UI | Kotlin, Jetpack Compose, Material 3 | Android 네이티브 및 반응형 화면 |
| 앱 구조 | MVVM, 단방향 상태 흐름, Repository 계층 | UI·도메인·데이터 책임 분리 |
| 로컬 저장 | Room, DataStore | 오프라인 데이터·사용자 설정 |
| 비동기 처리 | Coroutines, Flow, WorkManager | 데이터 갱신과 안정적인 예약 작업 |
| 지도 | Google Maps / 국내 지도 SDK 검토 | 장소 검색·지도 및 경로 표현 |
| 공동 편집 | Firebase Auth + Firestore 등 검토 | 인증·참가자·변경 동기화 |
| 첨부 파일 | Android 시스템 파일 선택기, 선택적 클라우드 저장 | 티켓·문서·사진 연결 |
| AI·OCR | 선택형 모듈, 온디바이스/서버 비용 비교 | 일정 보조·영수증 인식·요약 |
| 배포 | GitHub Actions + Google Play 테스트 트랙 | 빌드·검증·테스트 배포 |

처음에는 **단일 기기 로컬 MVP**를 완성하고, 공동 편집이 필요해지는 단계에서 인증·서버를 도입합니다. 외부 API 사용량과 비용 상한을 함께 설계합니다.

## 7. UI/UX 방향

- 콘셉트: **Travel Editorial** — 실제 여행 자료와 지도·사진이 중심인 절제된 에디토리얼 UI
- 라이트/다크/시스템 테마, 고대비 텍스트, 일관된 아이콘과 타이포그래피
- 카드·그림자·그라데이션 장식보다 정보 위계, 일정 가독성, 지도 조작을 우선
- 작은 휴대폰과 태블릿·폴더블 대응, 가로 모드와 글꼴 확대 검증
- 일정·지출의 수정 취소 및 삭제 확인, 오프라인/동기화 상태를 명확히 표시
- 초기 시안과 실제 Android 캡처를 화면별로 비교하여 개선

## 8. 개인정보 및 보안

- 위치·사진·문서 접근은 **필요한 시점에만 요청**, 거부해도 가능한 범위의 기능 제공
- 위치 기록과 자동 추적은 기본 비활성화
- 공유 여행은 최소 권한과 참가자별 접근 통제, 초대 취소·탈퇴 기능 설계
- 예약번호·개인정보가 로그·분석 도구·공개 공유 결과에 노출되지 않도록 검토
- 클라우드 동기화는 사용자 통제·데이터 삭제·내보내기 방안을 포함
- 지도·AI·클라우드 API 비밀키는 앱이나 저장소에 하드코딩하지 않음

## 9. 개발 로드맵

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 0 — 제품 명세 | 기능 우선순위, 데이터 모델, 화면 흐름, 권한·비용 조사 | MVP 범위와 핵심 화면 정의 |
| 1 — 앱 기반 | Compose 프로젝트, 디자인 시스템, 탐색, 로컬 DB, 테스트 기반 | 기본 탐색·저장·복구 정상 |
| 2 — 여행 MVP | 여행 생성·일정 CRUD·장소 수동 등록·체크리스트 | 오프라인에서 하나의 여행을 끝까지 관리 |
| 3 — 지도·경비 | 장소 검색·지도 연결·지출 입력·기본 정산 | 일정과 지도·금액 데이터가 일치 |
| 4 — 공동 여행 | 계정·참가자 초대·역할·동기화·충돌 처리 | 2대 이상 기기에서 공동 수정 검증 |
| 5 — 여행 중·기록 | 오늘 일정·체크인·사진 기록·리포트 | 여행 흐름 재현 및 기록 보존 |
| 6 — 고급 기능 | OCR, AI 일정 제안, 동선 최적화, 내보내기 | 사용자 승인·오류 처리·비용 통제 |
| 7 — 출시 준비 | 접근성, 권한, 보안, Android 실기기 QA, Play 테스트 | 핵심 시나리오 회귀 테스트 통과 |

**MVP 최우선:** 여행 생성 → 날짜별 일정 → 장소 저장 → 기본 지출 → 로컬 저장·복구.  
**초기 범위 제외:** 실제 항공·숙소 예약 대행, 결제 대행, 무동의 위치 추적, 자동 결제·일정 확정.

- 변경된 UI는 실제 Android 화면 캡처로 확인합니다.
- 초기 단계에서 계정·구독·과금·클라우드를 불필요하게 도입하지 않습니다.
- 상세 작업 지시와 디자인 시안, 검증 자료는 별도로 관리합니다.

## 16. 여행 일정·장소 관리 (2-B)

## 17. 준비물·경비 및 백업·복원 (2-C)

- [2-C 구현·재무 정밀도·JSON 복원 안정성·검증 기준](docs/02-C-checklist-expense-backup.md)
- Room 2→3 마이그레이션: 여행에 연결된 준비물/지출/총예산 테이블 추가. 기존 여행·일정·장소 데이터와 FK 관계 유지.
- S12: 준비물 이름 관리, 체크·해제, 전체/미완료 필터, 진행 수, 순서 저장, 삭제 후 즉시 복구.
- S09/S10: 총예산 설정, 지출 생성·편집·삭제, 날짜·시간·분류·메모·장소, BigDecimal 통화 정밀도 검증.
- 기본 통화 합계에는 같은 통화 지출만 포함하고, 미환산 다른 통화는 별도 표시합니다. 환율을 임의로 추정하지 않습니다.
- S20: Android 파일 선택기를 통한 UTF-8 JSON 백업(v1)·복원(여행·장소·일정·경비·예산·준비물).
- 복원 전 파일 형식·버전·여행 관계·금액 등을 검증하고 **기존 데이터 전체 교체**를 사용자에게 명시적으로 확인합니다. Room 트랜잭션 실패 시 원본이 유지되도록 설계했습니다.
- 백업 파일은 **암호화되지 않습니다**. 사진·첨부 문서·테마 설정은 포함되지 않습니다. 파일 최대 크기는 10MB입니다.
- CI를 통한 코드·DB·복원 자동 검증과 실제 Android 기기 UI/접근성 QA는 별도로 구분합니다.
- 공동 여행 정산/환율 스냅샷/지도·클라우드/Google Play 테스트 배포는 후속 단계입니다.


## 18. 지도·장소 검색 및 일정 연결 (3-A, PR #10)

- [3-A 외부 지도·검색 공급자, 데이터 모델·UX·검증 기준](docs/03-A-map-place-search.md)
- MapLibre Native Android + OpenFreeMap 스타일의 실제 지도에 Room 저장 장소 핀과 날짜별 일정 연결을 표시합니다.
- 장소 상세에 지도·좌표·공급자 및 조회 시각, 해당 장소에 연결된 일정 편집 경로를 제공합니다.
- 외부 장소 검색은 Photon 공개 데모에서 **명시적 버튼 클릭 시에만** 최대 8개 결과 조회합니다. 다수 사용자 서비스 출시 전 정식 공급자로 교체해야 합니다.
- Room v3→v4 마이그레이션으로 `provider`/원본 장소 ID/조회 시각을 추가하고 같은 여행의 같은 공급자 장소는 중복 등록하지 않습니다.
- JSON 백업 포맷 v2는 신규 공급자 정보를 포함하며 **기존 v1 파일도 복원**합니다. 기존 여행·일정·경비 데이터는 유지합니다.
- 실제 경로·이동 시간·거리를 제공하는 Route API와 GPS 위치 권한은 이번 범위에 없습니다. 제공자 미확인 값은 임의로 표시하지 않습니다.
- 코드 반영만으로 실기기 검증·스토어 배포 완료를 의미하지 않습니다. 3-A의 실제 Android 캡처 및 CI 상태는 PR #10에서 관리합니다.
